# Design system: colors

Every color in inturview is defined in one file: [`lib/theme.ts`](../lib/theme.ts). Change it there and it changes everywhere:
- the practice studio and hiring app
- the public site
- light and dark mode
- emails
- the error page
- the 2FA QR code

`npm run check:colors` runs in CI. It fails the build if a color is written anywhere else.

## How it fits together

```
palette          raw colors, each written once           ember[600] = "#C4541A"
   │
roles            what a color is for, per theme           light["text-ember"] = ember[600]
   │                                                      dark["text-ember"]  = ember[400]
   ▼
CSS variables    generated by Tailwind from the roles     --text-ember: 196 84 26
   │
   ├─ CSS        rgb(var(--text-ember))   rgb(var(--text-ember) / 0.18)
   ├─ Tailwind   text-text-ember   bg-accent/10   (tailwind.config.ts)
   └─ inline     inlineColors.button       (emails, global-error, QR code)
```

- **`palette`**: the brand's raw colors, grouped into scales.
  - `sand` holds the warm neutrals, from white to Char.
  - `ember` is the accent.
  - `green`, `amber` and `red` are used for scores.
  - `art` holds the practice-card illustration tints.
- **`light` / `dark`**: semantic roles. Components only ever name a role (`text-secondary`, `bg-inset`, `score-no`), never a palette color. `dark` must define every role `light` has, and TypeScript enforces it.
- **`fixed`**: roles that look the same in both themes:
  - the dialog overlay
  - shadows
  - the always-dark interview video stage
  - the email canvas
  - the illustration tints
- **`publicSite`**: overrides used only inside `.public-site` (the marketing pages): a deeper inverse band and a warmer surface.
- **`inlineColors`**: hex values for places CSS variables can't reach. Emails are always light.

Variables hold space-separated RGB triplets, not hex, so opacity works everywhere: `bg-bg/85` in Tailwind, or `rgb(var(--bg-page) / 0.85)` in CSS.

## Common changes

| I want to… | Edit |
| --- | --- |
| Change the brand accent everywhere | the `ember` scale in `palette` |
| Warm or cool all the neutrals | the `sand` scale |
| Change one use only, e.g. dark-mode muted text | that role in `dark` (point it at a different palette color) |
| Change score colors (hire / maybe / no) | `green` / `amber` / `red`, or the `score-*` roles |
| Change email colors | `inlineColors` (or the light roles it reads from) |

After editing, restart `npm run dev`, since Tailwind reads the config at startup. Check both themes; the theme toggle is in the nav.

## Adding a color

1. Add the raw value to `palette` if it's new.
2. Add a role. For a themed role, put it in both `light` and `dark`; TypeScript will complain if you miss one. For a role that's the same in both themes, put it in `fixed`.
3. Use it:
   - **CSS:** `rgb(var(--my-role))`.
   - **Tailwind:** add an entry in `tailwind.config.ts` under `colors`.
   - **Email:** read it through `inlineColors`.

## Static files

The nav and footer wordmark is drawn inline in `components/Brand.tsx` and follows the `brand-logo` role. A few files in `public/` are images that code can't recolor. Regenerate them when the logo color changes:
- `inturview-symbol.png` (the square symbol)
- `logo.svg` (the same wordmark, for use outside the app)
- `bimi-logo.svg` (the inbox logo shown by mail clients; it must stay a static SVG Tiny PS file)

## Rules

- No color literals outside `lib/theme.ts`. That covers hex, `rgb(…)` and `hsl(…)`, Tailwind palette classes like `text-white` or `bg-gray-500`, and CSS `white`/`black`. `check:colors` enforces this.
- A line that truly must keep a literal states why and ends with `// color-literal-ok`. Today the only one is Excalidraw's saved canvas background in `components/DesignSession.tsx`, which is scene data rather than a product color.
- Ember is the only accent. On the landing page, Instrument Serif italic in ember is reserved for one or two words.
- Never use pure white or pure black for a page background (`bg-page` is Parchment or Char).
